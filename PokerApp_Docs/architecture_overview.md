# Poker Preflop App — Архитектура и Структура Проекта (для NotebookLM)

Данный документ представляет собой подробное описание архитектуры, структуры данных и пользовательского интерфейса приложения `poker-preflop-app`. Он специально подготовлен для загрузки в NotebookLM с целью оценки, анализа и дальнейшей коррекции логики GTO-диапазонов.

## 1. Общий стек технологий
*   **Фреймворк:** React 18
*   **Сборщик:** Vite
*   **Стилизация:** Tailwind CSS (с кастомными градиентами и тенями для UI)
*   **Язык:** JavaScript (с использованием современных стандартов ES6+)
*   **Архитектурный паттерн:** Component-based UI с централизованным управлением состоянием в корневом компоненте.

## 2. Структура директорий
```text
poker-preflop-app/
├── package.json          # Зависимости и скрипты
├── vite.config.js        # Конфиг сборщика Vite
├── tailwind.config.js    # Настройки стилей Tailwind
├── src/
│   ├── main.jsx          # Точка входа React
│   ├── index.css         # Глобальные стили (включая директивы Tailwind)
│   ├── App.jsx           # Корневой компонент (State Manager)
│   ├── components/       # UI Компоненты
│   │   ├── PokerGrid.jsx        # Отрисовка матрицы рук 13x13
│   │   ├── ScenarioSelector.jsx # Переключатель сценариев (RFI / Vs RFI / 3-Bet)
│   │   └── StackSelector.jsx    # Выбор глубины стека
│   └── data/             # Бизнес-логика и данные
│       ├── rangeGenerator.js    # Основной движок генерации диапазонов
│       └── ranges.json          # (Устаревшая/резервная статичная база, заменяется генератором)
```

## 3. Управление состоянием (State Management)
Главный компонент `App.jsx` выступает в роли единого источника истины (Single Source of Truth) и хранит 5 ключевых переменных состояния, которые передаются вниз (prop drilling) в дочерние компоненты:

1.  `mode` (String): Режим игры — `'MTT'` или `'Cash'`.
2.  `position` (String): Позиция Хиро (Hero) — `'UTG', 'MP', 'HJ', 'CO', 'BTN', 'SB', 'BB'`.
3.  `stack` (String): Глубина стека в больших блайндах (bb) — дискретные значения от `8` до `200`.
4.  `scenario` (String): Текущий игровой сценарий — `'RFI'`, `'VSRFI'`, `'PUSH3B'`.
5.  `villainPos` (String): Позиция оппонента (злодея) — используется только в сценарии `'VSRFI'`.

## 4. UI Компоненты (Представление)

### `PokerGrid.jsx`
Самый сложный визуальный компонент. Отвечает за:
*   Генерацию сетки 13x13 (169 стартовых рук).
*   Определение типа руки (карманная пара, одномастная, разномастная).
*   Вызов функций из `rangeGenerator.js` (`getRFIRange`, `getVsRFIRange`) на основе текущего состояния (mode, stack, position, scenario).
*   **Цветовую кодировку (Color Mapping):**
    *   **RFI (Открытие):** Изумрудный (`bg-emerald-600`)
    *   **Микс RFI (Частичный рейз):** Изумрудная штриховка
    *   **Push / Олл-ин:** Красный (`bg-red-600`)
    *   **Колл:** Синий (`bg-blue-600`)
    *   **3-Бет (Рейз):** Оранжевый (`bg-orange-600`)
    *   **Микс 3-Бет/Колл:** Оранжево-синий градиент
    *   **Фолд:** Темно-серый (`bg-zinc-800`)
*   Отображение всплывающих подсказок (Tooltip) с подробной информацией о процентовках миксов.

### `ScenarioSelector.jsx`
Позволяет пользователю переключаться между:
*   **RFI (Raise First In):** Мы открываем торги первыми.
*   **Vs Raise (Защита/3-Бет):** Кто-то до нас сделал рейз. *Только в этом режиме появляется дополнительное меню выбора "Позиции рейзера" (Villain).*
*   **3-Бет Пуш:** Пуш-фолд чарты для коротких стеков.

### `StackSelector.jsx`
Отображает доступные стеки, разбитые на интуитивные группы (Крупные, Средние, Шорт-стек, Пуш/Фолд). Меняет визуальные акценты в зависимости от выбранной группы для улучшения UX.

## 5. Слой Данных и Бизнес-логика (`data/rangeGenerator.js`)
Это «мозг» приложения. Он не использует статичный громоздкий JSON, а генерирует диапазоны динамически на основе предписанных правил, упорядочивания (orderings) и математической интерполяции.

### Ключевые механизмы генерации:

1.  **Порядки рук (Orderings):**
    *   Определены массивы силы рук от самых сильных к самым слабым.
    *   Существуют РАЗНЫЕ порядки для `RFI` и `PUSH`. Например, в стеках 10bb пары ценятся выше разномастных тузов, что учтено в `PUSH_ORDER`, тогда как в глубоких стеках приоритеты иные (`RFI_ORDER`).
    *   Раздельное упорядочивание для `MTT` и `CASH`.

2.  **Счетчики комбинаций (Counts):**
    *   Вместо хранения 169 значений для каждого стека, хранятся "опорные точки" (anchors) в виде количества рук, которые нужно сыграть в конкретном стеке и позиции (`RFI_COUNTS`, `PUSH_COUNTS`).
    *   **Интерполяция (Interpolation):** Если пользователь выбирает стек, которого нет в справочнике (например, 28bb, если есть только 25 и 30), функция математически вычисляет нужное количество рук между этими двумя точками.

3.  **Порог Пуш-Фолда (Push Threshold):**
    *   В `MTT` при стеке `15bb` и ниже алгоритм жестко переключается с конструирования стандартного RFI диапазона на диапазон пуш-фолда.
    *   В `CASH` порог установлен на `5bb` (фактически это означает, что в кэше префлоп пуш-фолд не применяется, кэш-игроки играют рейзами даже со стеком 10-12bb).

4.  **Точные переопределения (Exact Range Overrides `RFI_EXACT`):**
    *   Позволяет игнорировать алгоритм интерполяции/подсчета для конкретных стеков/сценариев, где GTO-солвер выдает нелогистические или разорванные диапазоны (например, Cash, 20bb, UTG). В этих случаях используется заранее вбитый точный массив рук (`RFI_EXACT`).

5.  **Веса Миксов (Mixed Weights `MIXED_WEIGHTS`):**
    *   Выделенный объект для хранения рук, которые играются со смешанной частотой (например, карманные 55 с частотой 50% рейз, 50% фолд). Эта информация передается в `PokerGrid` для отрисовки застрахованных ячеек.

6.  **Матрица защиты Vs RFI:**
    *   Глубоко вложенный объект: `[Позиция Хиро] -> [Позиция Оппонента] -> [Глубина Стека (deep/mid/short)] -> { CALL: [], THREEBET: [] }`.

7.  **Гарантированный минимум (`GUARANTEED_RFI`):**
    *   Предохранительный механизм (Safety Net). Гарантирует, что при интерполяции определенных стеков премиум-руки (AA, KK, AKs) никогда не выпадут из диапазона открытия из-за математических округлений.

## 6. Что требует оценки и коррекции в платформе (NotebookLM)

При загрузке этого документа и/или исходных файлов в NotebookLM, фокус для ИИ-анализа должен быть следующим:
*   **Корректность массивов `RFI_ORDER` и `PUSH_ORDER`:** Точно ли соответствуют ранжирования рук современным GTO стандартам для соответствующих дисциплин?
*   **Адекватность интерполяции:** Достаточно ли опорных точек (stack counts) в `RFI_COUNTS` для плавного и безошибочного масштабирования диапазонов?
*   **Позиционные матрицы `VS_RFI`:** Проверка адекватности соотношения 3-бетов и коллов в разных глубинах (`deep`, `mid`, `short`). Отсутствуют ли ситуации "impossible scenarios" (например, SB vs BB).
*   **Обновление смешанных стратегий:** Наполнение словаря `MIXED_WEIGHTS` точными GTO-частотами.
